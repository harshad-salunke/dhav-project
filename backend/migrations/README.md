# DHAV — Database migrations (Supabase Postgres)

Run these in the **Supabase SQL Editor**. Two scenarios:

## A) Fresh / wiped database (the common case in test mode)

**Step 1 — schema:** run **`000_full_schema.sql`** — creates **every** table + index as they
exist today (001 + 003 + 004 folded together — the single source of truth). You do **not** need
001 / 002 / 003 / 004 on a fresh DB.

**Step 2 — seed:** fills the 4 marketplaces (69 categories, 157 subcategories, ~1000 products with
3–5 images each, 8 demo stores). Two ways:

- **Supabase SQL Editor** (it caps a single query at ~1 MB, so the full seed is split). Run the
  files in **`seed_parts/`** in order — paste one, Run, repeat:
  1. `005_part1_taxonomy.sql`            (reset + categories + subcategories — **run first**)
  2. `005_part2_products_grocery.sql`
  3. `005_part3_products_fruits.sql`
  4. `005_part4_products_electronics.sql`
  5. `005_part5_products_pharmacy.sql`
  6. `005_part6_stores.sql`              (demo stores)
  7. `005_part7_customers.sql`           (~33 demo customers for the admin Coverage map — **run last**)
- **psql / CLI** (no size cap): just run the single combined **`005_seed_marketplace.sql`**.

Both are self-resetting + safe to re-run (Part 1 / the combined file delete only the
`cat_/sub_/itm_/store_` seed rows first; your admin-created UUID rows are untouched).

## B) Existing database (apply changes incrementally)
The numbered history, applied in order:

| File | What it does |
|------|--------------|
| `001_initial_schema.sql` | Original tables (pre-marketplace). |
| `002_seed_catalog.sql` | Old 50-item grocery seed (superseded by 005 — skip on new setups). |
| `003_coming_soon_waitlist.sql` | "Notify me" waitlist table. |
| `004_marketplace_taxonomy.sql` | Adds `marketplace_type`/`store_type`, product fields, `categories` + `subcategories` tables. |
| `005_seed_marketplace.sql` | The big multi-marketplace seed (generated). |
| `007_variants_ratings_checkout.sql` | Adds `group_id` (unit-variant families) + `rating`/`rating_count` on products (seeds demo ratings), order checkout fields (`gstin`/`donation_amount`/`handling_charge`/`delivery_instructions`), and the `wishlist` table. **Run after 005.** Folded into `000_full_schema.sql` for fresh DBs (except the demo-rating back-fill — run 007 for that). |
| `008_marketplaces.sql` | Adds the **`marketplaces`** table (admin-configurable verticals: name/tab_label/emoji/colors/sort/enabled) and seeds the original 4. Makes the customer-app top tabs + theme DB-driven. Folded into `000_full_schema.sql`. |
| `009_stock_demo_stores.sql` | Stocks the 8 demo stores' `available_item_ids` + `inventory` with products of their own marketplace, so the customer app shows per-shop inventory (not the whole catalog). Two shops per marketplace get overlapping-but-different sets to test the "union of nearby stores" logic. **Run after 005.** Safe/re-runnable; touches only demo stores (`id LIKE 'store_%'`). For hand-picking products into a specific store, see `data_seed/assign_products_to_stores.sql`. |

> ℹ️ **Regenerating the seed:** `005_seed_marketplace.sql` is generated by
> `backend/scripts/build_seed.py` — edit the data tables there and re-run
> `python scripts/build_seed.py`, never hand-edit the `.sql`.
>
> ℹ️ **Admin image uploads** need a **public Supabase Storage bucket named `dhav-images`**.
