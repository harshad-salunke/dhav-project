# DHAV — Database migrations (Supabase Postgres)

All SQL is applied manually in the **Supabase SQL Editor** (there is no automatic
migration runner).

## A) Fresh / wiped database → use `data_init/`

The **`data_init/`** folder is the single source of truth for standing up a complete
database: `00_create_tables.sql` (full schema) then `01..07` (taxonomy, products per
marketplace, demo stores, demo customers). Open each file in order, paste, Run.
See **`data_init/README.md`** for details. Each file is under Supabase's ~1 MB
SQL-editor cap, and the seed steps are safe to re-run.

## B) Existing (live) database → apply numbered migrations incrementally

Only migrations **not yet applied** to the live DB remain here:

| File | What it does | Status |
|------|--------------|--------|
| `000_full_schema.sql` | The canonical full schema (source for `data_init/00_create_tables.sql`). Idempotent — safe to run on an existing DB to fill gaps. | reference |
| `010_call_masking.sql` | `call_logs` table for masked deliverer⇄customer calls. Folded into 000. | ⚠️ run in Supabase |
| `011_order_location_persist.sql` | `orders.last_lat/last_lng/last_location_at` live-tracking checkpoints. Folded into 000. | ⚠️ run in Supabase |

Migrations `001`–`009` were superseded (all folded into `000_full_schema.sql` /
`data_init/`) and have been deleted from the repo — their history is in git.

## Rule for every new schema change

1. Create a new numbered migration `0NN_*.sql` here (for pasting into the live DB).
2. Fold the same DDL into `000_full_schema.sql`.
3. Re-run `python scripts/build_seed.py` — it regenerates `data_init/` (copies 000
   into `00_create_tables.sql` and rebuilds the seed files).

> ℹ️ **Regenerating the seed:** `data_init/01..07` are generated by
> `backend/scripts/build_seed.py` — edit the data tables there and re-run it;
> never hand-edit the generated `.sql` (products carry `group_id` variant
> families + deterministic demo ratings).
>
> ℹ️ **Admin image uploads** need a **public Supabase Storage bucket named `dhav-images`**.
